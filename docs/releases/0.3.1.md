# GiviLoop 0.3.1

This patch fixes a completed browser review leaving the CLI process alive, and makes the first-use documentation shorter and reproducible.

## Fixed

Chrome helpers can inherit the browser's stderr pipe and keep it open after Chrome exits. GiviLoop had already saved the answer and closed its browser, but Node could keep waiting for that pipe. Cleanup now closes GiviLoop's own pipe after browser shutdown. It does not terminate unrelated Chrome processes or helpers.

A focused regression reproduces the inherited-pipe case: the old implementation times out; the corrected caller exits successfully while the synthetic helper remains alive. Existing shutdown, cancellation, profile persistence and browser round-trip checks remain in the suite.

## Documentation and examples

- Shorter README focused on Double Check and using existing chat access to avoid a separate API review charge where applicable.
- New recording of an actual browser review, saved response, MCP read and independent verification. The recording uses public example code and a dedicated terminal view, with no account UI or private conversations.
- `node examples/double-check/verify.mjs` reproduces the known bug and tests a candidate correction in memory; the source remains unchanged. The script does not execute reviewer output.
- Opt-in recording and live-check scripts, plus refreshed [end-to-end results](../e2e-validation-2026-09-21.md).

## Install

Download `giviloop-0.3.1.tgz` from this release and run:

```sh
npm install -g ./giviloop-0.3.1.tgz
givi --version
```

Node.js 20+ is required. This is a GitHub distribution; there is no npm registry publication. The 0.3.0 tag and package remain unchanged.

The [0.3.0 integration limits](0.3.0.md#release-scope-and-known-limits) still apply. Web access remains experimental, headless was blocked in the tested session, and technical success does not establish permission under provider terms. There is no measured total-token-savings claim.
